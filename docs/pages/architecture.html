System Architecture

GatiFleet is built as an 11-Tier Enterprise Monolith. This pattern prioritizes low latency, clean interfaces, and low compute costs by co-locating transactional databases, telemetry parsers, and neural logic steps within a single execution grid.

The 11 Tiers Explained

1. Frontend Tier (React + Vite)

An animated, context-driven workspace built on React 19 and Vite. Utilizes Framer Motion for UI transitions and Leaflet.js for real-time map plots.

2. Gateway Tier (Express API)

The centralized route entry point (located in server/index.js). Governs rate limits, CORS policies, helmet headers, and delegates payloads to downstream controllers.

3. Database ORM Tier (SQLite + Prisma)

Prisma ORM handles relational schemes, database migrations, and queries. A local SQLite database is utilized, eliminating external DB costs and reducing latency to microseconds for local queries.

4. Caching Tier (Node-Cache)

An in-memory Key-Value store to cache static route distances, customer credentials, and active driver locations. Minimizes redundant SQLite hits.

5. Real-Time Telemetry Tier (Socket.io)

Coordinates live bidirectional WebSocket channels. Subscribes client browsers to telemetry updates and parses incoming coordinate signals from the Reality Engine simulator.

6. Authentication Tier (JWT + bcrypt)

Token-based session authentication. Signs and verifies JSON Web Tokens (JWT) and hashes worker credentials via bcrypt.

7. Storage Tier (Multer Local Disk)

Multipart form-data middleware to process physical contract uploads, driver licensing documents, and invoice scans, storing them locally under the static public folder.

8. Job Queue Tier (FastQ)

An in-memory background worker queue. Offloads heavy computational tasks (such as driver roster rosters and route-optimization solvers) from the main API thread.

9. Intelligence Tier (Neural Engine)

Evaluates pricing models, constructs organizational charts, and executes heuristics to spot route deviations and mechanical failures.

10. Monitoring Tier (Winston + Morgan)

HTTP request logs (via Morgan) and custom system events (via Winston) are outputted to daily rotating files under server/logs/.

11. Process Management Tier (PM2)

Coordinates clustering, auto-restart triggers, and telemetry logs. Manages Node server health on production machines.
